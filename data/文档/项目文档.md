## 一、项目概述

### 1.1 目标
基于电子病历文本，自动识别老年患者是否存在**衰弱（Frailty）**状态，并提供结构化临床解释建议。

### 1.2 核心技术栈
| 组件 | 技术 | 说明 |
|------|------|------|
| 分类模型 | BERT (bert-base-chinese) | 二分类：衰弱 / 非衰弱 |
| 解释生成 | RAG + Ollama (qwen2.5:3b) | 检索增强 + 本地大模型 |
| 向量库 | ChromaDB + BGE-large-zh-v1.5 | 本地知识库检索 |
| GUI | PySide6 | 主应用程序界面 |
| 反馈系统 | SQLite + JSONL | 医生反馈收集与防丢失 |

### 1.3 评估标准
**Fried 衰弱表型标准**（5项，满足≥3项为衰弱）：
1. 不明原因体重下降
2. 疲乏/精力减退
3. 握力下降
4. 步速减慢
5. 活动量减少

### 3.3 第三阶段：持续学习路径（2026-07-20）

#### 修改9：BERT 增量微调

**核心策略**：
| 策略 | 原因 |
|------|------|
| 只取分歧样本 | 模型已预测对的样本再学无意义 |
| 冻结 BERT 底层 | 防止遗忘通用中文语义能力 |
| 小学习率 (1e-5) + 少 epoch (3) | 新数据量少，防止过拟合 |
| 保存为新版本 | 保留原模型，可对比 AUC 差异 |

**函数**：`incremental_finetune_bert(min_samples=50, output_dir=None)`


### 4.4 反馈数据用于模型优化

**阶段1（0-20条）**：只做收集，无操作

**阶段2（20-50条）**：**全自动触发** —— 每次提交反馈后，系统自动检查分歧样本数，达到 20 条时自动调用 `update_prompt_with_feedback()` 更新 `FEW_SHOT_EXAMPLE`，无需手动操作。

**阶段3（50-100条）**：**全自动触发** —— 分歧样本达到 50 条时，系统在后台线程中自动启动 `incremental_finetune_bert()`，训练完成后生成新版本模型（如 `frailty_bert_demo_model_v2`）。BERT 模型支持**热切换**（`reload_bert_model()`），无需重启程序即可加载新模型。

**阶段4（100+条）**：**全自动触发** —— 分歧样本达到 100 条时，系统自动启用 `_ENABLE_SIMILAR_CASES = True`，此后每次生成 LLM 解释时，自动检索最相似的历史分歧案例嵌入 Prompt。

### 自动学习调度器核心逻辑

```python
# 阶段阈值配置（可自定义）
STAGE_THRESHOLDS = {
    "prompt_update": 20,    # 阶段2：自动更新 Prompt
    "bert_finetune": 50,    # 阶段3：自动增量微调 BERT
    "similar_cases": 100,   # 阶段4：启用动态相似案例嵌入
}

def _check_and_trigger_learning():
    """
    每次 save_feedback 后自动调用。
    检查反馈数量，达到阈值时自动触发对应优化阶段。
    已触发的阶段记录到 _triggered_stages，避免重复触发。
    """
    stats = get_feedback_stats()
    disagreements = stats["disagreements"]
    
    # 阶段2：≥20 条分歧 → 自动更新 Prompt
    if disagreements >= 20 and "prompt_update" not in _triggered_stages:
        update_prompt_with_feedback()
        _triggered_stages.add("prompt_update")
    
    # 阶段3：≥50 条分歧 → 后台自动微调 BERT
    if disagreements >= 50 and "bert_finetune" not in _triggered_stages:
        thread = AutoFinetuneThread()  # QThread 后台执行
        thread.start()
        _triggered_stages.add("bert_finetune")
    
    # 阶段4：≥100 条分歧 → 启用动态相似案例
    if disagreements >= 100 and "similar_cases" not in _triggered_stages:
        _ENABLE_SIMILAR_CASES = True
        _triggered_stages.add("similar_cases")
```

### BERT 热切换机制

```python
def reload_bert_model(model_path):
    """运行时热切换 BERT 模型，不重启程序"""
    global tokenizer, model, device
    tokenizer, model, device = load_bert_model(model_path)
    print(f"🔄 BERT 模型已热切换至：{model_path}")
```

**触发时机**：用户提交反馈后 → `_check_and_trigger_learning()` 自动检查 → 后台微调完成 → 新模型保存 → 用户可选择热切换或下次启动自动加载最新版本。

## 五、已知问题与限制

| 问题 | 影响 | 缓解措施 |
|------|------|----------|
| 3B 模型约束效果有限 | LLM 格式错误 | 3 次重试 + Few-shot + 校验 |
| 病历缺失 Fried 指标 | 评估不可靠 | 缺失 ≥3 项时警告用户 |
| 混淆疾病体征与衰弱 | 结论错误 | 反馈收集 + Prompt 强调鉴别 |
| 知识库缺少专科指南 | 建议不专业 | 可扩展 ChromaDB 内容 |
| BERT 只在假数据上训练 | 真实场景准确率未知 | 增量微调需真实标注 |

## 十、使用建议

### 日常使用中医生需要做什么

| 操作 | 频率 | 说明 |

| 正常评估 | 每次 | 粘贴病历 → 快速预测/详细解释 |

### 系统管理员需要做什么

| 阶段 | 数据量 | 系统行为 | 管理员操作 |
|------|--------|----------|------------|
| 阶段1 | 0-20 条 | 只收集 | 无 |
| 阶段2 | 20-50 条 | **自动**更新 Prompt | 无 |
| 阶段3 | 50-100 条 | **自动**后台微调 BERT | 可选：热切换新模型 |
| 阶段4 | 100+ 条 | **自动**嵌入相似案例 | 无 |

### 热切换 BERT 模型的方法

```python
# 在 Python 交互式环境中或添加菜单按钮
from frailty_assessment_app import reload_bert_model

# 切换到最新版本
reload_bert_model("./frailty_bert_demo_model_v2")

# 或自动检测最新版本
import os
base = "./frailty_bert_demo_model"
versions = [d for d in os.listdir(".") if d.startswith(base + "_v")]
latest = sorted(versions, key=lambda x: int(x.split("_v")[-1]))[-1]
reload_bert_model(latest)
```

## 十一、批量病历标注与全量重训练（`batch_annotation_tool.py`）

### 适用场景

当你拿到医院脱密处理的大量历史病历时，可以用这个工具：
1. **批量导入** → 自动 BERT + LLM 预标注
2. **人工审核** → 修正错误标注
3. **一键重训练** → 全量训练 BERT（比增量微调更充分）

### 与反馈收集的区别

| 对比 | 反馈收集（运行时） | 批量标注（离线） |
|------|------------------|----------------|
| 数据来源 | 医生使用中发现错误 | 历史脱密病历 |
| 标注方式 | 医生逐条反馈 | 批量预标注 + 人工审核 |
| 数据量 | 慢积累（几十条） | 快导入（几百上千条） |
| 训练方式 | 增量微调（冻结底层） | 全量重训练（解冻多层） |
| 适用阶段 | 系统上线后持续优化 | 系统上线前冷启动 / 定期大补 |

### 使用流程

```bash
cd source

# 步骤1：导入脱密病历（CSV/Excel）
python batch_annotation_tool.py import /path/to/hospital_records.csv
# 输出：自动 BERT 预标注，不确定样本标记

# 步骤2：LLM 详细预标注（可选，对不确定样本）
python batch_annotation_tool.py auto-llm 100

# 步骤3：查看待审核记录
python batch_annotation_tool.py review 10
# 输出：JSON 格式的记录列表，含 BERT/LLM 预标注结果

# 步骤4：人工审核标注（逐条或批量）
python batch_annotation_tool.py label 42 衰弱 张医生
python batch_annotation_tool.py label 43 非衰弱 张医生

# 步骤5：查看标注质量
python batch_annotation_tool.py analyze

# 步骤6：全量重训练 BERT（融合反馈 + 批量标注数据）
python batch_annotation_tool.py retrain 200 5
# 参数：最少200条样本，训练5个epoch
# 输出：frailty_bert_retrained_v2/ + training_report.json

# 步骤7：导出标注数据
python batch_annotation_tool.py export ./my_annotated_data.csv
```

### 全量重训练 vs 增量微调

| 对比 | 增量微调（运行时） | 全量重训练（批量标注） |
|------|------------------|----------------------|
| 数据量 | 50-200 条 | 200-2000+ 条 |
| 解冻层数 | 仅分类头 | 最后 3 层 Transformer + 分类头 |
| 学习率 | 1e-5（极小） | 2e-5（标准） |
| Epoch | 3 | 5-10 |
| 训练时间 | 几分钟 | 十几分钟到几小时 |
| 效果 | 轻量修正 | 充分适应医院数据分布 |
| 触发方式 | 自动（50条分歧） | 手动运行 retrain 命令 |

### 数据质量检测

批量标注工具自动检测：
- **不确定样本**：BERT 置信度 < 0.7，优先人工审核
- **BERT-LLM 一致性**：两者结论不一致的样本，需要重点审核
- **类别平衡**：衰弱/非衰弱比例是否均衡

```bash
python batch_annotation_tool.py analyze
# 输出示例：
# 总记录数：500
# 已人工标注：320 (64.0%)
# BERT 不确定样本：85
# BERT-LLM 一致性：245/320 (76.6%)
```

### 新增后台线程

为避免 UI 阻塞，新增 3 个 `QThread` 子类：

| 线程类 | 用途 | 触发按钮 |
|--------|------|----------|
| `BatchImportThread` | 后台导入 CSV/Excel，BERT 预标注 | 步骤1 |
| `BatchLLMThread` | 后台调用 LLM 详细预标注 | 步骤2 |
| `BatchRetrainThread` | 后台全量重训练 BERT | 步骤6 |

```python
class BatchImportThread(QThread):
    finished_signal = Signal(int, int, str)  # imported, skipped, message
    # 调用 import_batch_records()，完成后发信号更新 UI

class BatchLLMThread(QThread):
    finished_signal = Signal(int, str)  # annotated, message
    # 调用 auto_annotate_with_llm()

class BatchRetrainThread(QThread):
    finished_signal = Signal(str, str)  # model_path, message
    # 调用 full_retrain_bert()
```

### 人工审核交互流程

1. 点击【加载待审核记录】→ 从 `batch_annotation.db` 读取未标注记录
2. 表格优先显示**不确定样本**（黄色背景高亮）
3. 选中一行 → 点击【衰弱/衰弱前期/非衰弱】按钮
4. 自动调用 `submit_manual_label()` → 同时写入 `feedback.db`
5. 已标注行从表格移除 → 状态栏显示成功消息

### 模型重训练交互流程

1. 设置最少样本数（默认100）和 Epoch（默认5）
2. 点击【全量重训练 BERT】→ 确认对话框
3. 后台线程执行 `full_retrain_bert()`
4. 训练完成后弹出提示：是否热切换到新模型？
5. 选择"是" → 调用 `reload_bert_model()` 立即生效

| 功能 | CLI (`batch_annotation_tool.py`) | GUI (新面板) |
